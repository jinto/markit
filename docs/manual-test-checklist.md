# 수동 테스트 체크리스트

```
swift run MarkitApp
```

`⌘1` WYSIWYG / `⌘2` 소스 / `⌘3` 분할 · `⌘K` 커맨드 팔레트 · `⌘O` 열기 · `⌘S` 저장

자동으로 검증할 수 없는 것들만 모았다. 나머지는 `swift test`가 지킨다.

각 항목은 **왜 자동화가 안 되는지**를 함께 적었다. 나중에 자동화할 방법이 생기면
여기서 빼고 테스트로 옮긴다.

---

## 1. 한글 IME 조합

> **자동화 불가 사유:** 조합(marked text) 상태는 IME와 `NSTextInputClient`의
> 왕복으로만 만들어진다. `insertText(_:replacementRange:)`로는 재현되지 않는다.
> 이 프로젝트에서 자동 검증이 안 되는 유일한 핵심 영역이다.

- [ ] 조합 중 재스타일 패스가 조합을 끊지 않는가
      - `ㅎ` → `하` → `한` 을 천천히 입력. 중간에 글자가 확정되어 버리면 실패
- [ ] 조합 중 커서가 조합 문자 뒤에 머무는가
- [ ] `**굵게` 를 조합 중일 때 마커가 깜빡이지 않는가
      - 재스타일이 조합 중에 돌면 `**` 가 숨었다 나타났다 할 수 있다
- [ ] 조합을 마치지 않은 상태로 화살표 키를 눌렀을 때 (조합이 확정되고 커서가 이동해야 한다)
- [ ] 조합 중 외부 파일 변경이 들어왔을 때 — 에이전트 협업 경로
      - 다른 터미널에서 파일을 수정. 조합이 깨지거나 입력이 사라지면 실패
- [ ] 한글 강조가 실제로 기울어 보이는가
      - `*기울임*` 을 입력하고 커서를 다른 줄로 옮긴다. 한글에는 이탤릭 페이스가 없어
        `.obliqueness`로 직접 기울이므로, **눈으로 확인해야 한다**

## 2. 언두

> **자동화 불가 사유:** 헤드리스 테스트 프로세스에서 `undoManager`가 `nil`이다
> (`allowsUndo = true`여도). 창이 필요하다.

- [ ] 타이핑 후 ⌘Z가 글자를 되돌리고 스타일이 따라오는가
- [ ] 스타일링 패스가 언두 스택에 별도 항목을 쌓지 않는가
      - 쌓이면 ⌘Z를 두 번 눌러야 한 글자가 지워진다. 속성 변경은 `.editedAttributes`만
        내므로 이론상 안전하지만 확인해야 한다
- [ ] 마커가 숨겨진 구간을 지운 뒤 ⌘Z
- [ ] 외부 리로드(`setMarkdown`) 후 ⌘Z가 리로드를 되돌리지는 않는가

## 3. 숨긴 마커 위에서의 캐럿

> **자동화 불가 사유:** 자동 검증은 되지만 **판정이 주관적이다.** 0.01pt로 접힌
> 마커 위에서 캐럿이 제자리처럼 보이는 것은 의도된 절충이고, 그것이 참을 만한지는
> 써 봐야 안다. (표시용 문단에서 글자를 지우는 대안은 캐럿을 완전히 깨뜨려서
> 배제했다 — 계획서 사실 4번)

- [ ] 숨긴 `**` 위에서 →를 누르면 캐럿이 두 번 제자리처럼 보인다. 참을 만한가
- [ ] 숨긴 마커를 가로질러 드래그 선택 — 선택 영역이 이상하게 보이지 않는가
- [ ] 줄 끝을 클릭했을 때 캐럿이 숨긴 마커 뒤로 가는가
- [ ] ⌥→ (단어 단위 이동)이 숨긴 마커를 자연스럽게 건너뛰는가
- [ ] Home/End가 숨긴 마커 안쪽에 멈추지 않는가

## 4. 자동 치환이 원문을 오염시키지 않는가

> **자동화 불가 사유:** 스마트 인용부호·대시 치환은 실제 키 입력 경로에서만 발화한다.
> 헤드리스에서 `insertText`로는 재현되지 않는다.

- [ ] `"` 를 입력했을 때 `“` 로 바뀌지 않는가 (코드블록 안 문자열이 깨진다)
- [ ] `'` 를 입력했을 때 `‘` 로 바뀌지 않는가
- [ ] `---` 를 입력했을 때 `—` 로 바뀌지 않는가 (구분선이 망가진다)
- [ ] `...` 가 `…` 로 바뀌지 않는가
- [ ] 서식 있는 텍스트를 붙여넣었을 때 서식이 따라오지 않는가

## 5. 큰 문서

> **자동화 불가 사유:** 측정은 자동으로 되지만 **"느껴지는가"는 사람이 판단한다.**
> 측정값은 계획서 사실 7번에 있다 (32KB: 키당 15ms, 325KB: 키당 155ms).

- [ ] 32KB 문서에서 타이핑 지연이 느껴지는가
- [ ] 325KB 문서에서 실제로 못 쓸 정도인가 — 증분 재파싱 착수 근거
- [ ] 큰 문서에서 스크롤이 매끄러운가 (TextKit 2의 게으른 레이아웃이 일하는지)
- [ ] 큰 문서에서 화살표 연타 시 커서가 끈적하지 않은가
      - 같은 줄 안 이동은 재스타일을 건너뛰도록 했다. 그게 충분한지 확인

## 6. 세 모드와 분할 프리뷰

> **자동화 불가 사유:** 정책 매핑과 프리뷰 동기화는 `EditorSessionTests`가 지킨다.
> **보기에 맞는지**는 사람이 판단한다.

- [ ] `⌘1` WYSIWYG: 커서가 있는 줄만 마커가 드러나는가. 줄을 옮길 때 튀지 않는가
- [ ] `⌘2` 소스: 모든 마커가 보이고 색으로 구분되는가
- [ ] `⌘3` 분할: 왼쪽 원문 / 오른쪽 접힌 프리뷰. 타이핑이 오른쪽에 따라오는가
- [ ] 분할에서 타이핑이 무겁지 않은가 (파싱이 두 번 일어난다 — 손익분기점이 16KB)
- [ ] 모드를 여러 번 왕복한 뒤 저장했을 때 파일이 그대로인가
- [ ] 분할 경계를 드래그해 폭을 바꿨을 때 양쪽 줄바꿈이 따라오는가
- [ ] `⌘K` 팔레트에서 한글 질의가 되는가. 매치 글자 하이라이트가 제 글자에 붙는가

## 7. 다크 모드

> **자동화 불가 사유:** 색은 semantic color로 지정했으므로 값은 자동으로 따라오지만,
> **읽을 수 있는지는 봐야 안다.**

- [ ] 다크 모드에서 마커(`tertiaryLabelColor`)가 너무 흐려 안 보이지 않는가
- [ ] 다크 모드에서 인라인 코드 배경이 본문과 구분되는가
- [ ] 시스템 테마를 바꿨을 때 즉시 따라오는가
